# B2B Research & Outreach Agent

MVP для поиска потенциальных клиентов на внедрение ИИ-автоматизации. Первая ниша исследования сайтов — русскоязычные оптовые поставщики упаковки, расходных материалов и промышленной комплектации. Результат — проверяемые наблюдения, гипотезы, приоритет исследования и черновики. Дополнительно настраиваются автоматические email-отклики на конкретные публичные объявления заказчиков.

Два направления: продажи (приём и квалификация обращений, подбор позиций и КП, помощь с повторными контактами) и документы. Соответствие нише, возможная польза и интерес клиента учитываются отдельно. Каталог, CRM и контакт на сайте не подтверждают спрос.

## Установка (Python 3.12+)

```bash
uv sync --frozen --extra dev
uv run b2b-agent init --config config.json
uv run b2b-agent run --config config.json --csv examples/sites.csv
uv run b2b-agent export --db output/research.sqlite --output output/export
uv run pytest -q
uv run ruff check src tests
```

`uv.lock` фиксирует зависимости. Crawl4AI использует HTTP-стратегию: Playwright/Chromium скачивать не требуется. При отсутствии uv можно установить `pip install -e '.[dev]'`, но разрешение версий тогда не фиксировано. Команда init не перезаписывает существующий файл. CLI-код возврата: 0 — все компании обработаны без ошибок; 2 — пустой результат, частичный/неудачный запуск или ошибка команды.

В этой облачной среде нет прямого DNS к внешним сайтам; используйте `examples/config.json` с `dns_mode: proxy` и штатным HTTPS_PROXY. В обычной среде оставьте безопасный по умолчанию `dns_mode: local`.

CSV в UTF-8, обязательная колонка `website` (другие игнорируются):

```csv
website
https://supplier.example
```

Адрес нормализуется до корня сайта. HTTP/HTTPS и www-варианты одного домена не создают дублей, вложенные субдомены считаются отдельными компаниями. Разные домены одной организации требуют ручного объединения. В повторном запуске последнее исследование заменяет предыдущую запись домена, журнал ошибок сохраняется.

## Настройки

Пример — [examples/config.json](examples/config.json). `max_companies`, `max_pages`, `delay_seconds`, `timeout_seconds`, `user_agent`, `niche_keywords`, `sender` управляют объёмом исследования и черновиком. Укажите в User-Agent реальный контакт оператора при регулярном обходе. Сайты из примера — кандидаты для проверки доступности, не подтверждённые лиды.

Поиск через Brave Web Search API (платный/квотируемый сервис):

```json
{"search": {"provider": "brave", "api_key_env": "BRAVE_API_KEY", "queries": ["оптовая упаковка поставщик каталог"], "limit": 5}}
```

Список поиска объединяется с CSV и дедуплицируется. Без CSV необходим настроенный поиск. Разрешите `api.search.brave.com`, ключ `BRAVE_API_KEY` добавьте через защищённые настройки среды. При ошибке поиска CSV всё равно обрабатывается; ошибка сохраняется в SQLite и журнале.

### Поиск компаний с публичным запросом

`search.queries` ищет сайты компаний; `search.request_queries` — публикации о поиске подрядчика. Эти потоки разделены: сайт биржи или сообщества не становится компанией-клиентом. Примеры запросов включены в конфигурацию по умолчанию. Для реального поиска нужен `search.provider: brave` и ключ.

```bash
uv run b2b-agent find-requests --config config.json --output output/requests
```

`request_candidates.json` содержит URL публикации, запрос, заголовок и сниппет. Каждый результат имеет статус `unverified_search_hit`: выдача поиска может содержать рекламу исполнителей, архивы, вакансии и пересказы. Она ещё не является доказательством спроса.

Откройте конкретную публикацию, проверьте автора, дату, открытый статус запроса, соответствие вашей услуге и связь с компанией. Сохраните найденный сайт компании и **точный URL запроса**, не общую ленту, в CSV:

```csv
website,request_url
https://supplier.example,https://community.example/requests/123
```

Адреса выше вымышленные, не лиды. После проверки:

```bash
uv run b2b-agent run --config config.json --requests-csv requests.csv
```

Можно одновременно передать `--csv`. Агент исследует сайт компании и отдельно получает явно указанные страницы запросов с проверкой robots.txt. Из внешней публикации извлекаются только цитаты запроса; контакты площадки, её ниша и каталог не переносятся в карточку компании. Лимиты: `max_pages` на сайт плюс `max_request_pages` (по умолчанию 2) на явно заданные источники. Внешние ссылки публикаций не обходятся.

`qualification.interest` равен `unconfirmed` либо `public_request_to_verify`. Публичный запрос — основание проверить актуальность, автора и связь с компанией; код не подтверждает их автоматически. Подтверждённый интерес устанавливается только в общении с клиентом, которого в MVP пока нет. `next_step` предлагает пропуск, проверку релевантности или проверку запроса. Компания вне настроенной ниши сохраняется для проверки, но черновик не создаётся.

### Подход к первому обращению

Сообщение прямо обозначает предложение услуги, описывает один сценарий и спрашивает об актуальности. Без критики сотрудников и процессов, выдуманных потерь, обещаний роста продаж, притворного исследования рынка и давления на созвон. Можно предложить короткий пример; изменения в системах и обращения к клиентам согласует команда заказчика.

Текст сайта и сформулированные LLM вопросы не вставляются в сообщение. Черновик исследования компании собирается из фиксированных нейтральных сценариев только для подходящей ниши с доказательствами соответствующего процесса. Отдельный режим автооткликов описан ниже. Отказ — основание исключить адрес из дальнейших обращений.

### Автоотклики через Gmail

Режим `auto-reply`: поиск объявлений → повторное чтение страницы с robots.txt → проверка задачи, даты и адреса для откликов → письмо → журнал отправки. Объявления могут относиться к любой отрасли; соответствие услугам задаётся в `outreach.workflows` (продажи и документы), отдельно от оптовой ниши исследования сайтов.

Пример настроек — [examples/outreach-gmail.json](examples/outreach-gmail.json). Пока `outreach.enabled=false`, создаются только предпросмотры. Укажите свой реальный `from_email` и подпись `signature`. Для работающего Python-агента Gmail API требует OAuth с правом `gmail.send` и offline-доступом: задайте `GMAIL_CLIENT_ID`, `GMAIL_CLIENT_SECRET`, `GMAIL_REFRESH_TOKEN` в защищённых настройках среды. При запуске access token обновляется через HTTPS. Подключение Gmail к чату само по себе не передаёт эти секреты Python-процессу.

```bash
uv run b2b-agent auto-reply --config examples/outreach-gmail.json --dry-run
# После настройки почты и outreach.enabled=true:
uv run b2b-agent auto-reply --config config.json
```

С ранее найденными кандидатами (объявления всё равно читаются заново):

```bash
uv run b2b-agent auto-reply --config config.json --requests-json output/requests/request_candidates.json
```

При `outreach.enabled=true` обычный `run` также запускает поиск объявлений и автоотклики. `run --dry-run` выполняет исследование и предпросмотр без отправки. Расписание не создаётся: один вызов CLI — один запуск агента.

Автоматически обрабатывается отдельная HTML-страница с единственным заголовком задачи, датой публикации не старше 30 дней, прямым запросом заказчика и единственным email, явно указанным для откликов в тексте объявления. Поддерживаются `article`/`main`, даты JSON-LD, `time`, `article:published_time` и русская подпись «Опубликован». Ленты, вакансии, закрытые, просроченные и неоднозначные объявления получают `needs_review`; при указании обязательного отклика через площадку email не отправляется. Контакты подвала и поддержки не используются. Это консервативные HTML-правила; площадке с иной разметкой может понадобиться адаптер.

Письмо содержит название и ссылку на объявление, подходящий сценарий помощи и предложение согласовать бюджет и срок после уточнения объёма. Агент не обещает уложиться в произвольный бюджет или срок. Текст письма собирается шаблоном, без инструкций LLM или сайта.

`outreach.json` содержит результаты и подготовленные письма. Таблицы `outbound_messages` и `suppressed_emails` находятся в SQLite из `--db`. По умолчанию: максимум 5 попыток за запуск, 10 за день по Москве и пауза 30 дней для одного адресата. На одно объявление повторный отклик не отправляется; одинаковые заголовки для одного адреса также дедуплицируются между площадками. Учитываются даже попытки с неопределённым исходом. Используйте одну постоянную БД при повторных запусках.

Запись `sending` резервируется транзакцией **до** отправки. `sent` означает принятие сообщения почтовым сервисом, а не доставку во входящие. После таймаута или сбоя с неопределённым исходом — `uncertain`; автоматического повтора нет. Запись `sending`, оставшаяся после падения процесса, также не отправляется повторно. Ответы, отказы и bounce автоматически не читаются. Исключить адрес после отказа можно командой:

```bash
uv run b2b-agent suppress-email --db output/research.sqlite --email customer@example.com
```

Альтернатива Gmail API — `outreach.provider=smtp`, `smtp_host=smtp.gmail.com`, порт 465, `smtp_security=ssl`. Переменные `OUTREACH_SMTP_USER` и `OUTREACH_SMTP_PASSWORD` содержат логин и пароль приложения (при его доступности в аккаунте). Поддерживается STARTTLS, открытый SMTP без TLS не поддерживается. В облачной среде для SMTP необходим разрешённый TCP-доступ; Gmail API работает через штатный HTTPS-прокси.

Любой совместимый с OpenAI Chat Completions HTTPS API:

```json
{"llm": {"enabled": true, "base_url": "https://api.openai.com/v1", "api_key_env": "B2B_LLM_API_KEY", "model": "gpt-4o-mini"}}
```

Передайте ключ через переменную `B2B_LLM_API_KEY` и разрешите hostname выбранного API в сети. Ключей в коде и JSON нет; `.env` автоматически не загружается. API должен поддерживать `response_format: json_object`. По умолчанию LLM выключена: гипотезы создаются прозрачными правилами и помечаются `analysis_mode=rules`. Включённая LLM без ключа или с невалидным ответом даёт явную ошибку и partial-результат. Гипотезы правил могут сохраниться, но черновик при ошибке анализа не создаётся. Наличие корректного JSON и citation-ID не гарантирует смысловую достоверность LLM.

## Результаты

`output/research.sqlite`, `output/results.json`, `output/results.csv`, `output/errors.log`. Ошибки содержат этап, тип и HTTP-статус, без тел ответов провайдеров и ключей. JSON хранит источники каждого факта и контакта, ID доказательств гипотез, время, причины оценки и неизвестные параметры. CSV содержит вложенные массивы как JSON и защищает текстовые ячейки от spreadsheet formula injection. Файлы output игнорируются Git; храните контакты локально и задавайте срок удаления.

Поля `icp`, `sales`, `documents` и `automation` — индикаторы по наблюдаемым сигналам, не подтверждение размера компании, её потребностей или ручной работы. `qualification` экспортируется в JSON и CSV вместе со ссылками на доказательства. Прочитайте [архитектуру](docs/architecture.md) и [отчёт проверки](docs/validation.md).

## Структура

```text
src/b2b_agent/
  cli.py          # init / run / export
  config.py       # проверяемая конфигурация
  models.py       # Fact, Contact, Hypothesis, Score, Research
  discovery.py    # CSV, Brave, канонизация
  crawler.py      # HTTP, robots, Crawl4AI, лимиты
  analysis.py     # извлечение, гипотезы, LLM, score, draft
  pipeline.py     # оркестрация и изоляция ошибок
  storage.py      # SQLite и экспорт
examples/         # конфигурация и seed CSV
tests/           # unit и интеграционные тесты
docs/            # архитектура и проверка
```

## Ограничения MVP

- Исследуются только статические HTML-страницы: нет JS, PDF/Excel-каталогов, CAPTCHA, логина или отправки форм. Robots.txt — обязательная проверка, но не заменяет условия использования сайта.
- Редиректы пропускаются; CSV должен содержать канонический URL. При закрытом robots.txt, ошибке сети, запрете или rate limit — журнал, без обхода защиты.
- Нет проверки размера компании, выручки, доставляемости email или личности контактного лица. Извлекаются видимые буквальные email и российские телефоны; скрытые/обфусцированные контакты могут быть пропущены.
- Поиск и реальный LLM API требуют отдельных ключей/доступа. Автотесты используют mock API; реальные вызовы не заявляются как проверенные без ключей.
- Ключевые слова и оценка эвристические; нужен человек для проверки цитат, вопросов, адресатов и правомерности обращения. Перед отправкой проверьте также ограничения на unsolicited outreach.
- Нет CRM, фонового расписания, multi-user доступа и истории версий. Gmail/SMTP требуют отдельной настройки доступа; чтение входящих и обработка bounce отсутствуют. База, файлы и логи локальные; нагрузка последовательная.
