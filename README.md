# B2B Research & Outreach Agent

MVP для поиска потенциальных клиентов на внедрение ИИ-автоматизации. Первая ниша — русскоязычные оптовые поставщики упаковки, расходных материалов и промышленной комплектации. Результат — проверяемые наблюдения, гипотезы, приоритет исследования и **черновики**, без автоматической отправки.

## Установка (Python 3.12+)

```bash
uv sync --frozen --extra dev
uv run b2b-agent init --config config.json
uv run b2b-agent run --config config.json --csv examples/sites.csv
uv run b2b-agent export --db output/research.sqlite --output output/export
uv run pytest -q
uv run ruff check src tests
```

`uv.lock` фиксирует зависимости. Crawl4AI использует HTTP-стратегию: Playwright/Chromium скачивать не требуется. При отсутствии uv можно установить `pip install -e '.[dev]'`, но разрешение версий тогда не фиксировано. Команда init не перезаписывает существующий файл. CLI-код возврата: 0 — все компании обработаны без ошибок; 2 — пустой результат, частичный/неудачный запуск или ошибка команды.

В этой облачной среде нет прямого DNS к внешним сайтам; используйте `examples/config.json` с `dns_mode: proxy` и штатным HTTPS_PROXY. В обычной среде оставьте безопасный по умолчанию `dns_mode: local`.

CSV в UTF-8, обязательная колонка `website` (другие игнорируются):

```csv
website
https://supplier.example
```

Адрес нормализуется до корня сайта. HTTP/HTTPS и www-варианты одного домена не создают дублей, вложенные субдомены считаются отдельными компаниями. Разные домены одной организации требуют ручного объединения. В повторном запуске последнее исследование заменяет предыдущую запись домена, журнал ошибок сохраняется.

## Настройки

Пример — [examples/config.json](examples/config.json). `max_companies`, `max_pages`, `delay_seconds`, `timeout_seconds`, `user_agent`, `niche_keywords`, `sender` управляют объёмом исследования и черновиком. Укажите в User-Agent реальный контакт оператора при регулярном обходе. Сайты из примера — кандидаты для проверки доступности, не подтверждённые лиды.

Поиск через Brave Web Search API (платный/квотируемый сервис):

```json
{"search": {"provider": "brave", "api_key_env": "BRAVE_API_KEY", "queries": ["оптовая упаковка поставщик каталог"], "limit": 5}}
```

Список поиска объединяется с CSV и дедуплицируется. Без CSV необходим настроенный поиск. Разрешите `api.search.brave.com`, ключ `BRAVE_API_KEY` добавьте через защищённые настройки среды. При ошибке поиска CSV всё равно обрабатывается; ошибка сохраняется в SQLite и журнале.

Любой совместимый с OpenAI Chat Completions HTTPS API:

```json
{"llm": {"enabled": true, "base_url": "https://api.openai.com/v1", "api_key_env": "B2B_LLM_API_KEY", "model": "gpt-4o-mini"}}
```

Передайте ключ через переменную `B2B_LLM_API_KEY` и разрешите hostname выбранного API в сети. Ключей в коде и JSON нет; `.env` автоматически не загружается. API должен поддерживать `response_format: json_object`. По умолчанию LLM выключена: гипотезы создаются прозрачными правилами и помечаются `analysis_mode=rules`. Включённая LLM без ключа или с невалидным ответом даёт явную ошибку и partial-результат. Гипотезы правил могут сохраниться, но черновик при ошибке анализа не создаётся. Наличие корректного JSON и citation-ID не гарантирует смысловую достоверность LLM.

## Результаты

`output/research.sqlite`, `output/results.json`, `output/results.csv`, `output/errors.log`. Ошибки содержат этап, тип и HTTP-статус, без тел ответов провайдеров и ключей. JSON хранит источники каждого факта и контакта, ID доказательств гипотез, время, причины оценки и неизвестные параметры. CSV содержит вложенные массивы как JSON и защищает текстовые ячейки от spreadsheet formula injection. Файлы output игнорируются Git; храните контакты локально и задавайте срок удаления.

Поля `icp` и `automation` — индикаторы по наблюдаемым сигналам, не подтверждение размера компании, её потребностей или ручной работы. Прочитайте [архитектуру](docs/architecture.md) и [отчёт проверки](docs/validation.md).

## Структура

```text
src/b2b_agent/
  cli.py          # init / run / export
  config.py       # проверяемая конфигурация
  models.py       # Fact, Contact, Hypothesis, Score, Research
  discovery.py    # CSV, Brave, канонизация
  crawler.py      # HTTP, robots, Crawl4AI, лимиты
  analysis.py     # извлечение, гипотезы, LLM, score, draft
  pipeline.py     # оркестрация и изоляция ошибок
  storage.py      # SQLite и экспорт
examples/         # конфигурация и seed CSV
tests/           # unit и интеграционные тесты
docs/            # архитектура и проверка
```

## Ограничения MVP

- Исследуются только статические HTML-страницы: нет JS, PDF/Excel-каталогов, CAPTCHA, логина или отправки форм. Robots.txt — обязательная проверка, но не заменяет условия использования сайта.
- Редиректы пропускаются; CSV должен содержать канонический URL. При закрытом robots.txt, ошибке сети, запрете или rate limit — журнал, без обхода защиты.
- Нет проверки размера компании, выручки, доставляемости email или личности контактного лица. Извлекаются видимые буквальные email и российские телефоны; скрытые/обфусцированные контакты могут быть пропущены.
- Поиск и реальный LLM API требуют отдельных ключей/доступа. Автотесты используют mock API; реальные вызовы не заявляются как проверенные без ключей.
- Ключевые слова и оценка эвристические; нужен человек для проверки цитат, вопросов, адресатов и правомерности обращения. Перед отправкой проверьте также ограничения на unsolicited outreach.
- Нет CRM, Gmail, рассылок, фонового расписания, multi-user доступа и истории версий. База, файлы и логи локальные; нагрузка последовательная.
